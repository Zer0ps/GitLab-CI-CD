# Финальные шаги и интеграция

Описание пайплайна GitLab CI/CD, используемых переменных и проверки успешного деплоя.

## CI/CD пайплайн

Пайплайн включает три этапа:

- `test`: установка зависимостей и запуск `pytest`.
- `docker-test`: сборка и проверка Docker-образа.
- `deploy`: деплой на удалённый сервер через SSH.

Минимальная структура `.gitlab-ci.yml`:

```yaml
stages:
  - test
  - docker-test
  - deploy

# Пример содержимого заданий опущен; в проекте используются кэширование pip и проверка приложения через curl в отдельных контейнерах
```

Главное замечание: для многострочных shell-команд используйте символ `>` — это предотвращает ошибки парсинга YAML.

## Секреты и переменные

В GitLab добавьте переменные окружения:

- `VDS_HOST` — IP или доменное имя сервера деплоя.
- `VDS_USER` — пользователь для подключения по SSH.
- `VDS_KEY` — приватный SSH-ключ (добавляется в CI/CD Variables).

## Тестовый деплой

На машине `Deploy-UB` подготовьте приложение:

- Клонируйте репозиторий.
- Добавьте `deploy.sh` с командами перезапуска сервиса или Docker-контейнера.
- Убедитесь, что пайплайн проходит от начала до конца и разворачивает приложение.

## Итог

Развёрнутый проект автоматически:

- запускает тесты;
- собирает Docker-образ;
- проверяет его работу;
- публикует результат на целевом сервере.
