# Финальные шаги и интеграция

Описание пайплайна GitLab CI/CD, переменных и проверки успешного деплоя.

## 1. Базовая структура `.gitlab-ci.yml`
```yaml
stages:
  - test
  - docker-test
  - deploy

variables:
  DOCKER_DRIVER: overlay2
  DOCKER_TLS_CERTDIR: ""

workflow:
  rules:
    - if: $CI_PIPELINE_SOURCE == "push"

test:
  stage: test
  image: python:3.12
  script:
    - pip install -r requirements.txt
    - pytest

build-image:
  stage: docker-test
  image: docker:25.0.2
  services:
    - docker:25.0.2-dind
  script:
    - docker build -t $CI_REGISTRY_IMAGE:test .
    - docker run --rm $CI_REGISTRY_IMAGE:test pytest
  rules:
    - if: $CI_COMMIT_BRANCH == "main"

deploy:
  stage: deploy
  image: alpine:3.19
  before_script:
    - apk add --no-cache openssh-client rsync
    - eval "$(ssh-agent -s)"
    - echo "$VDS_KEY" | tr -d '\r' | ssh-add -
    - mkdir -p ~/.ssh && chmod 700 ~/.ssh
    - echo "StrictHostKeyChecking no" >> ~/.ssh/config
  script:
    - rsync -avz . $VDS_USER@$VDS_HOST:/opt/app
    - ssh $VDS_USER@$VDS_HOST "cd /opt/app && ./deploy.sh"
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
```

### Ключевые моменты
- Используйте символ `>` для многострочных shell-команд, если объединяете их в одной строке.
- В `build-image` включён Docker-in-Docker для сборки и проверки образа.
- Перед деплоем синхронизируется директория проекта и вызывается `deploy.sh` на целевом сервере.

## 2. Переменные окружения в GitLab
Добавьте в **Settings → CI/CD → Variables**:
- `VDS_HOST` — IP или домен сервера деплоя.
- `VDS_USER` — пользователь SSH.
- `VDS_KEY` — приватный SSH-ключ в формате OpenSSH.
- При работе с GitLab Registry: `CI_REGISTRY_USER`, `CI_REGISTRY_PASSWORD` (если требуется push образов).

## 3. Подготовка сервера деплоя (`Deploy-UB`)
1. Установите Docker/Compose или нужные системные зависимости приложения.
2. Создайте каталог `/opt/app` и файл `deploy.sh` с логикой перезапуска (systemd или `docker compose`).
3. Проверьте, что SSH-ключ из переменной `VDS_KEY` авторизован в `~/.ssh/authorized_keys` пользователя.

Пример `deploy.sh`:
```bash
#!/usr/bin/env bash
set -euo pipefail
cd /opt/app

docker compose pull
docker compose up -d --build
```

## 4. Проверка пайплайна
1. Сделайте коммит в ветке `main` и запустите пайплайн.
2. Убедитесь, что раннер активен и выполняет задания.
3. После завершения убедитесь, что приложение обновилось на `Deploy-UB` (проверьте HTTP-ответ или логи сервиса).

## 5. Итог
Развёрнутая конфигурация автоматически:
- запускает тесты;
- собирает и проверяет Docker-образ;
- разворачивает приложение на целевом сервере.
